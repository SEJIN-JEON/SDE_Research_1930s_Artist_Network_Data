# 1930년대 예술가 네트워크 재편찬 데이터셋

논문 「학술적 디지털 판본(Scholarly Digital Edition)으로서의 데이터 재편찬 — 1930년대 예술가 네트워크 데이터를 중심으로」의 재편찬 데이터셋, 변환 코드, 검증 자료 일체를 공개하는 저장소입니다.

이 저장소는 논문의 부속 자료가 아니라 논문이 수행한 편찬 작업 그 자체의 산출물입니다. 논문은 동일한 원천 자료라 하더라도 어떤 편찬 원칙을 적용하는가에 따라 상이한 해석 가능성이 열린다고 주장하며, 그 주장의 근거가 되는 데이터·규칙·검증 절차를 여기에 모두 공개합니다.

## 3. 데이터 구조

관계 중심 데이터 구조란 인물과 기관을 단순히 연결하는 데 그치지 않고, 그 연결 자체를 하나의 독립적인 기술 대상으로 삼는 구조를 뜻합니다. 각 관계 발생 기록은 세 층위로 표현됩니다.

```turtle
# (1) 기본 트리플 — 인물과 기관의 연결
person:P007842 art:authored inst:I000228 .

# (2) 인용 트리플 — 그 연결을 주어로 삼아 관계 발생 기록에 연결
<< person:P007842 art:authored inst:I000228 >> art:hasOccurrence rel:R00039212 .

# (3) RelationOccurrence — 시기·출처·비고·판본을 결합한 독립 기술 단위
rel:R00039212 a art:RelationOccurrence ;
    art:subject person:P007842 ;
    art:predicate art:authored ;
    art:object inst:I000228 ;
    art:year "1939"^^xsd:gYear ;
    art:attributeLabel "발표매체" ;
    art:note "1권 2호(193903), 詩" ;
    art:source "연구자" ;
    art:sourceRow "데이터수정!39213" ;
    art:edition edition:재편찬판본 .
```

논문 본문의 예시는 지면 제약상 축약 구문(인용 트리플에 속성을 직접 부여)으로 표기하였으나, 두 표기는 동일한 구조를 가리킵니다. 산출 파일에서는 완전 중복 행을 각각 독립적으로 보존해야 하므로 층위를 명시적으로 풀어 씁니다.

### 술어 이층 구조

| 상위 술어 | 하위 술어 | 원천 속성 | 건수 |
|---|---|---|---:|
| `art:participatesIn` | `art:studiedAt` | 학교 | 1,320 |
| | `art:memberOf` | 소속단체 | 684 |
| | `art:workedAt` | 직장 | 1,092 |
| `art:publishedIn` | `art:authored` | 발표매체 (기본값) | 48,601 |
| | `art:issued` | 발표매체 (비고에 '발행') | 15 |
| | `art:edited` | 발표매체 (비고에 '편집') | 0 |
| | `art:contributedTo` | 스키마상 정의, 현 판본에 사례 없음 | 0 |
| | `art:printed` | 스키마상 정의, 현 판본에 사례 없음 | 0 |
| (없음) | `art:bornIn` | 출생 | 84 |

학교·소속단체·직장 관계는 인물이 특정 기관에 소속되어 활동하였다는 공통의 성격을 지니므로 `art:participatesIn` 아래에 배치하였습니다. 발표매체 관계는 소속 여부가 아니라 매체에 대해 어떤 역할을 수행하였는가의 문제이므로 `art:publishedIn`을 상위 술어로 두었습니다. 출생 관계는 한 인물에 대해 하나의 값만을 가지는 단일한 사실이므로 상위 술어 없이 독립된 술어로 남겨 두었습니다.

### 식별자 규약

`relation_id`의 번호 n과 `art:sourceRow`의 엑셀 행 번호 n+1 사이에는 1:1 대응이 성립합니다(헤더 1행 보정). 변환 과정에서 원천 시트의 행 순서를 어떤 단계에서도 재배열하지 않기 때문입니다. 이 규약은 검증 2단계에서 51,796행 전체에 대해 확인됩니다.

## 4. 편찬상의 결정

데이터 편찬은 기계적 변환이 아니라 판단의 연속입니다. 무엇을 근거로 어떤 관계를 확정했는지에 대한 판단의 기록을 남기지 않은 데이터는 후속 연구자가 검증하기 어렵습니다. 주요 결정과 그 근거를 아래에 밝힙니다. 전체 목록은 `excel_to_rdfstar_mapping.yml`의 `editorial_decisions` 항목에 있습니다.

**완전 중복 행의 보존 (11,698행)** — 원천 8개 필드가 모두 동일한 행이라도 병합하지 않고 각각 독립적인 관계 발생 기록으로 보존하였습니다. 예컨대 김관호와 도쿄미술학교의 1911년 관계는 원천에 두 행으로 기록되어 있는데, 하나는 사사관계를 확인할 수 있다는 비고를 담고 다른 하나는 비고 없이 같은 연도의 관계만을 반복합니다. 기존 방식이라면 둘 중 하나를 대표값으로 선택하고 나머지를 지웠겠지만, 하나의 관계에 대하여 서로 다른 자료가 서로 다른 정보를 제공할 때 그 차이를 병합하여 지우지 않고 병렬적으로 남겨 두려는 설계 원칙에 따라 두 기록을 모두 보존하였습니다. 이는 서로 다른 해석의 가능성을 데이터 단계에서 미리 하나로 좁히지 않으려는 장치이기도 합니다.

**출처의 '연구자' 표기 (2,458행)** — 문헌으로 확인되지 않는 관계를 `연구자`로 표시해 둔 것은 공란을 채우기 위한 임시 처리가 아니라, 각 관계가 어떤 검증 단계에 있는지를 데이터 구조 자체에 남겨 두려는 장치입니다. 이후의 연구가 어느 관계부터 우선적으로 문헌을 대조해야 하는지를 데이터가 스스로 드러내도록 합니다.

**조광의 직장 관계 (7행)** — `6. Notes` 시트의 "직장에서 조광 삭제" 결정은 식별자 사전(`2.Workplace_Info` 시트)에 적용된 것으로, 원천 관계 데이터에는 해당 7건이 그대로 남아 있습니다. 관계 발생 기록은 원천 51,796행 전체를 대상으로 하며, 이는 논문이 보고하는 직장 1,092건과 정합합니다.

**식별자 사전의 참조 범위** — 식별자 사전의 일부 조인 테이블이 아직 미완성 상태이므로, RDF-Star 변환에서는 원천 데이터셋의 행 단위 기록을 관계 발생 기록의 기준으로 삼고 식별자 사전은 인물 및 기관을 특정하는 데에만 참조하였습니다.

**인물 식별자의 단계적 해소 (172행)** — 동일 인물이 여러 행에 등장할 때 직업·국적 필드가 일부 행에서만 공란으로 기재된 사례가 48명에게서 확인됩니다. 이에 (작가, 직업, 국적) 완전일치를 우선하고, 실패 시 (작가, 국적) → (작가) 순으로 후보가 유일할 때에만 완화하여 해소하였습니다. Person_Info의 작가 이름은 10,440명 전원이 유일하므로 최종 단계에서 해소가 보장되며, 미해결 행은 0건입니다. 완화가 적용된 172행은 `person_matching_exceptions.csv`에 전수 기록하였습니다.

## 5. 검증

### 검증 설계의 전제

코드가 오류 없이 실행되는 것과 코드의 논리가 옳은 것은 별개의 문제입니다. 파서가 오류를 내지 않는다는 사실은 산출물이 문법적으로 유효하다는 뜻일 뿐, 변환 로직이 원천 데이터를 정확하게 반영하였다는 뜻이 아닙니다. 잘못된 규칙으로 일관되게 변환된 데이터도 문법적으로는 완벽하게 유효합니다.

이에 이 저장소는 세 단계로 검증합니다. 나아가 검증 도구 자체가 오류를 탐지할 수 있는지를 별도로 확인합니다. 검증이 "오류 0건"을 보고하였다는 사실만으로는 데이터가 정확하다고 단정할 수 없으며, 검증 스크립트에 결함이 있어 오류를 탐지하지 못하는 경우에도 동일한 결과가 나오기 때문입니다.

### 실행

```bash
pip install pandas openpyxl rdflib==7.6.0

python3 build_dataset.py                                        # 데이터셋 생성
python3 validate_dataset.py --confidence 0.99 --margin 0.03     # 3단계 검증
python3 mutation_test.py --injections 500                       # 검증 도구 탐지력 확인
```

### 1단계 — 구문 검증

산출된 TTL이 유효한 RDF/Turtle 구문인지 rdflib 7.6.0으로 확인합니다.

| 파일 | 결과 |
|---|---|
| `schema.ttl` | 94 triples 파싱 성공 |
| `persons.ttl` | 39,554 triples 파싱 성공 |
| `institutions.ttl` | 2,325 triples 파싱 성공 |
| `relations_rdfstar.ttl` | 588,297 triples 파싱 성공 (인용 트리플 51,796개 치환 후) |

rdflib 7.6.0은 RDF-Star의 인용 트리플 구문(`<< ... >>`)을 지원하지 않으므로, 해당 구문을 임시 URI로 치환한 뒤 나머지 문법을 검증합니다. 전체 구문 검증은 Apache Jena, Oxigraph, GraphDB 등 RDF-Star 지원 파서에서 가능합니다.

### 2단계 — 전수 정합성 검증

51,796행 전체에 대해 집계 수준의 불변식 13개 항목을 확인합니다. 현재 13개 항목 전부 통과합니다.

| 항목 |
|---|
| 행 수 보존 (원천 51,796 = 산출 51,796) |
| `relation_id` 연속성 (결번·중복 없음) |
| `relation_id` ↔ `sourceRow` 규약 (n ↔ n+1) |
| `sourceRow`의 원천 범위 내 존재 |
| 인물·기관 식별자 참조 무결성 |
| 인물·기관 식별자 유일성 |
| 술어 미배정 행 없음 |
| 출처 공란 없음 |
| 판본 정보 단일 |
| 관계 유형별 빈도 보존 |
| 술어 계층 정합 (속성 → 술어 대응) |

### 3단계 — 신뢰구간 기반 표본 검증

전체에서 통계적으로 정당화되는 크기의 표본을 무작위로 추출하고, 각 표본을 원천 엑셀 파일로 직접 되짚어 8개 필드 전부를 재대조합니다. 이때 재대조 로직은 `build_dataset.py`를 호출하지 않고 독립적으로 다시 구현하여, 변환 스크립트의 오류가 검증 스크립트에 그대로 전이되지 않도록 합니다.

표본 크기는 Cochran 공식에 유한모집단 보정을 적용하여 산정합니다.

```
n₀ = z² · p(1−p) / e²
n  = n₀ / (1 + (n₀ − 1) / N)
```

`p`는 사전 정보가 없으므로 분산이 최대가 되는 0.5로 보수적으로 설정합니다(가장 큰 표본 크기를 요구하는 값). 오류율의 구간 추정에는 Wilson score interval을 사용합니다. 정규근사(Wald) 구간은 관측 오류율이 0에 가까울 때 구간 폭이 0으로 붕괴하여 무의미해지므로, 이 경우에도 타당한 상한을 제공하는 Wilson 구간이 적합합니다.

| 신뢰수준 | 허용오차 | 표본크기 | 시드 | 오류 | 오류율 95% Wilson 신뢰구간 |
|---|---|---:|---:|---:|---|
| 99% | ±3.0%p | 1,780 | 42 | 0 | [0.000%, 0.215%] |
| 99% | ±3.0%p | 1,780 | 777 | 0 | [0.000%, 0.215%] |
| 99% | ±3.0%p | 1,780 | 20260906 | 0 | [0.000%, 0.215%] |
| 95% | ±5.0%p | 382 | 1930 | 0 | [0.000%, 0.996%] |

서로 다른 시드와 신뢰수준 조합으로 4회 독립 실행한 결과 모두 오류가 0건이었습니다. 99% 신뢰수준 표본(n=1,780) 기준으로 모집단 전체의 오류율은 95% 신뢰구간 상한 0.215% 이하로 추정됩니다.

### 검증 도구의 탐지력 확인

정상 데이터에 알려진 수의 오류를 의도적으로 주입한 뒤, 표본 검증이 그 오류를 통계적으로 기대되는 수준에서 탐지하는지 확인합니다. 모집단 N에 오류 K건을 주입하고 크기 n의 표본을 뽑을 때 표본에 포함되는 오류 건수는 초기하분포 Hypergeom(N, K, n)을 따르므로, 관측된 탐지 건수가 그 예측구간 안에 들어오면 검증 도구가 정상 작동한다고 판단합니다.

오류 주입과 표본 추출에는 반드시 독립적인 난수 시드를 사용합니다. 동일한 시드를 쓰면 주입 대상이 표본에 그대로 포함되어 탐지력이 실제보다 과대평가됩니다.

| 항목 | 값 |
|---|---|
| 주입 오류 | 500건 (`year`, `source`, `predicate`, `note` 필드에 분산) |
| 참 오류율 | 0.9653% |
| 표본 크기 | 1,780 |
| 기대 탐지 건수 | 17.18 |
| 실제 탐지 건수 | 28 |
| 99% 초기하 예측구간 | [8, 28] |
| 판정 | 정상 작동 |

## 6. 알려진 한계

**복수 역할의 단일 술어 처리** — 비고에 '편집'과 '발행'이 함께 나타나는 1건(`데이터수정!15780`, "박길룡 편집 및 발행(1940.4-1940.11)")은 발행을 우선 판정하여 `art:issued` 하나로만 분류됩니다. 편집 역할은 술어로 반영되지 않고 `art:note` 원문에만 보존됩니다. 한 관계 발생 기록당 하나의 술어만 부여하는 현재 스키마의 구조적 제약입니다.

**미사용 술어** — `art:contributedTo`와 `art:printed`는 스키마상 정의되어 있으나 현 판본에서 해당 사례가 확인되지 않습니다. `art:edited` 역시 위 복수 역할 사례가 발행으로 판정되어 실제 배정 건수는 0입니다.

**연도 정보의 단순화** — 년도 필드에 범위나 추정이 표기된 경우 정규식으로 첫 네 자리만 추출합니다. 원문 표기는 `art:note`에 보존되지만, `art:year`만으로 질의할 경우 종료 시점 정보는 반영되지 않습니다.

**출처 표기의 불일치** — 출처 문자열에 동일 문헌의 표기가 통일되지 않은 사례가 있습니다(예: '나미가타 츠요시'와 '나미카타 츠요시'). 원문 보존 원칙에 따라 변환 단계에서 임의로 통합하지 않았으며, 원천 데이터 차원의 교정 대상입니다.

**문헌출처 확인률의 편차** — 소속단체 관계의 문헌출처 확인률은 17.5%로 낮습니다. 이들 관계의 상당수는 연구자가 선행 연구나 개별 인물 조사를 통해 이미 알고 있던 사실로 먼저 입력된 뒤, 그 사실을 뒷받침하는 문헌을 하나씩 대조하여 뒤늦게 확인해야 하는 항목입니다. 출처를 확보한다는 것은 참고문헌 목록에 항목 하나를 추가하는 일이 아니라, 연구자가 암묵적으로 알고 있던 지식을 관계 발생 기록이 요구하는 명시적 근거로 전환하는 작업입니다. 인물 한 명 한 명을 개별적으로 검토해야 하는 만큼 더디게 진행될 수밖에 없습니다.

**판본의 잠정성** — 이 데이터셋은 완결된 정본이 아니라 지속적으로 갱신되는 디지털 판본입니다. 현재는 두 번째 판본에 해당하며, 후속 연구가 이 데이터를 토대로 다른 관심사를 향하여 확장하는 것을 전제로 공개합니다.
